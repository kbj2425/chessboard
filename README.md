# Clubhouse Chess — DB 없는 실시간 웹 체스 플랫폼

Node.js(Express + Socket.io) 메모리 저장소 + 브라우저 LocalStorage만으로 동작하는
1v1 / 2v2(팀) / 4인 자유대전 체스 플랫폼입니다. Render.com 무료 웹 서비스 + UptimeRobot
헬스체크로 24/7 구동을 목표로 설계했습니다.

## 폴더 구조

```
webchess/
├── server.js          # Express + Socket.io 서버, 인메모리 저장소, 방/타이머/전적 로직
├── chessEngine.js      # 규칙 엔진 (서버·클라이언트 공용, UMD 모듈)
├── package.json
└── public/
    ├── index.html      # 로그인/로비/게임 단일 페이지
    ├── style.css        # 월넛 & 브라스 클럽하우스 테마
    └── client.js        # 소켓 클라이언트, 보드 렌더링, 드래그앤드롭, 채팅 등
```

## 로컬 실행

```bash
npm install
npm start
# http://localhost:3000 접속
# 헬스체크: http://localhost:3000/ping , /health
```

테스트 계정은 회원가입 화면에서 임의의 아이디로 만들면 됩니다(기본 안내 비밀번호: `123456`,
서버가 강제하지는 않습니다). 두 개의 브라우저 창(또는 시크릿 창)을 열어 서로 다른 계정으로
로그인하면 실시간 대국을 테스트할 수 있습니다.

## 구현 현황 및 설계상 단순화 사항

요구사항 전체를 하나의 실행 가능한 프로젝트로 옮기면서, 규칙이 명확히 정의되지 않은
부분은 아래와 같이 **구체적인 규칙을 정하여** 구현했습니다. 실제 서비스로 다듬을 때
참고하세요.

| 항목 | 구현 내용 |
|---|---|
| 헬스체크 | `GET /ping`(텍스트), `GET /health`(JSON) 구현 완료 |
| 로그인/회원가입 | 서버 메모리 `Map` + 토큰 기반 세션. 새로고침 시 LocalStorage에 저장된 토큰으로 자동 재로그인 |
| 시간 제어 | 무제한 / 1분 / 5분 / 10분 / 15분+3초 피셔 프리셋. 서버가 권위적으로 타이머 계산, 시간 초과 시 자동 패배 처리 |
| 표준 규칙 | 캐슬링·앙파상·프로모션·체크·체크메이트·스테일메이트·3수 동형 반복·50수 규칙 모두 구현 (1v1 기준). `chessEngine.js`에 유닛 테스트로 확인(폴스 메이트, 캐슬링, 앙파상 시나리오) |
| UX | 클릭 이동 + 드래그앤드롭 동시 지원, 이동 가능 칸 점 표시, 사전 수(premove) 자동 실행, 잡힌 기물 바, 무르기/기권/무승부 제안 구현 |
| 복기 모드 | 대국 종료 후 "복기하기" 버튼 → 기보를 처음부터 재생하며 이전/다음 탐색 |
| **2v2 팀 체스 (16x8)** | 각 팀이 보드 폭 16칸에 자기 세트(0-7열)·동료 세트(8-15열)를 나란히 배치. **턴은 팀 단위로 화이트→블랙 교대**하며, 해당 팀의 접속한 아무 플레이어나 수를 둘 수 있습니다(동시에 두 명이 시도하면 먼저 서버에 도달한 수만 반영). 팀에 킹이 2개 남아있는 동안은 자기 킹이 체크에 노출되는 수도 허용(첫 킹 희생 가능), 킹이 1개만 남으면 표준 체크 회피 규칙이 적용됩니다. 팀 전용 채팅 탭 제공 |
| **4인 자유대전 (십자형 보드)** | 14x14 바운딩 박스에 중앙 8x8 + 4방향 날개를 배치한 십자형 보드. 턴은 p1→p2→p3→p4 시계 방향 고정 순서로 진행되며, **각자 자신의 킹에 대해서만 표준 체크/체크메이트 규칙이 적용되는 자유대전(개인전) 방식**입니다. 체크메이트(또는 기권) 시 해당 플레이어는 탈락 처리되고 남은 한 명이 최종 승자가 됩니다. 프로모션은 중앙 8x8의 정중앙 4칸(d4/d5/e4/e5 상당 좌표) 진입 시 발동 |
| 로비/초대/관전/재접속 | 방 목록 실시간 갱신, 온라인 유저 목록, 우편함 초대(수락 시 자동 입장), 관전자 소켓 룸 참가, 재접속 시 "진행 중인 대국" 배너로 원클릭 복귀 |
| 전적/통계 | 서버 메모리에 승/무/패 누적, 로비 사이드바에 표시. 팀전은 팀 전체, 4인전은 승자 1명 외 전원 패로 집계 |

### 의도적으로 남겨둔 단순화(운영 전 검토 필요)

- **DB 미사용이 요구사항이므로** 서버 재시작 시 모든 계정/전적/대국 기록이 초기화됩니다.
  Render 무료 플랜은 배포/슬립 복귀 시 프로세스가 재시작될 수 있어, 영구 보존이 필요하면
  추후 Redis/Postgres 등의 외부 저장소 연동을 고려하세요.
- 4인 모드는 "캡처 더 킹" 대신 표준 체크메이트 판정을 적용했지만, 4개의 킹이 얽힌 복잡한
  다중 체크 시나리오(예: 한 수로 두 플레이어가 동시에 체크당하는 경우)는 러프하게
  "각 킹에 대해 개별적으로 공격 여부만 판정"하는 방식으로 처리했습니다. 대회급 엄밀함이
  필요하면 추가 케이스 스터디가 필요합니다.
- 2v2/4인 모드에서는 삼수 동형 반복·50수 규칙 자동 무승부 판정을 생략했습니다(1v1만 적용).
- 4인 보드는 화면 방향을 항상 "p1이 아래쪽" 고정으로 렌더링합니다(다른 플레이어별 보드
  회전은 구현하지 않음). 필요 시 `client.js`의 `orientationFlip()`을 확장하세요.
- 무르기(takeback)는 상대 동의 시 **마지막 한 수만** 되돌리는 방식으로 구현했습니다.
- 채팅/초대 등은 스팸 방지, 신고 기능 없이 최소 기능만 구현되어 있습니다.

## 배포 가이드

### 1단계 — GitHub 업로드

```bash
cd webchess
git init
git add .
git commit -m "Clubhouse Chess: DB 없는 실시간 웹 체스 플랫폼"
git branch -M main
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

`node_modules/`는 `.gitignore`에 포함되어 있으니 커밋하지 않아도 됩니다.

### 2단계 — Render.com 배포

1. [Render 대시보드](https://dashboard.render.com) → **New +** → **Web Service** 선택
2. 방금 만든 GitHub 저장소를 연결
3. 설정값
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start` (내부적으로 `node server.js` 실행)
   - **Instance Type**: Free
4. 환경 변수는 필수 아님(서버가 `process.env.PORT`를 자동으로 사용)
5. **Create Web Service** 클릭 → 빌드/배포 로그 확인 → 배포 완료 시 `https://<서비스명>.onrender.com` 형태의 URL 발급
6. 배포 후 `https://<서비스명>.onrender.com/ping` 접속해 `pong` 응답이 오는지 확인

> Render 무료 플랜은 일정 시간 요청이 없으면 인스턴스가 슬립 상태로 전환됩니다.
> 슬립 상태에서 첫 요청은 콜드 스타트로 수십 초가 걸릴 수 있습니다 — 3단계의
> UptimeRobot 핑으로 이를 방지합니다.

### 3단계 — UptimeRobot 연동 (슬립 방지)

1. [UptimeRobot](https://uptimerobot.com)에 가입/로그인
2. **+ Add New Monitor** 클릭
3. 설정값
   - **Monitor Type**: HTTP(s)
   - **Friendly Name**: Clubhouse Chess Keepalive
   - **URL**: `https://<서비스명>.onrender.com/ping` (또는 `/health`)
   - **Monitoring Interval**: 5 minutes (무료 플랜 최소 간격)
4. 저장하면 5분 간격으로 헬스체크 핑이 전송되어 Render 인스턴스가 슬립 상태로
   전환되기 전에 계속 깨어있게 됩니다.
5. Render 무료 플랜의 슬립 유예 시간(통상 15분 유휴)보다 짧은 간격으로 핑이
   오므로, 이론적으로는 24/7 응답 가능한 상태가 유지됩니다. 다만 Render 정책은
   변경될 수 있으니 공식 문서를 함께 확인하세요.

### 4단계 — 배포 후 점검 체크리스트

- [ ] `/ping`, `/health` 모두 200 응답
- [ ] 두 브라우저(혹은 시크릿 창)로 각각 회원가입 후 1v1 방 생성 → 참가 → 수 이동이
      실시간으로 반영되는지 확인
- [ ] 새로고침 후 토큰 기반 자동 재로그인이 되는지 확인
- [ ] 대국 중 새로고침(연결 끊김) 후 로비의 "재접속하기" 배너로 복귀되는지 확인
- [ ] UptimeRobot 대시보드에서 모니터가 "Up" 상태로 표시되는지 확인

## 소켓 이벤트 요약 (확장 시 참고)

| 방향 | 이벤트 | 설명 |
|---|---|---|
| C→S | `auth:register` / `auth:login` / `auth:resume` | 계정 생성/로그인/토큰 재개 |
| C→S | `lobby:createRoom` / `lobby:joinRoom` / `lobby:spectate` / `lobby:invite` | 방 생성/참가/관전/초대 |
| C→S | `game:move` / `game:premove` / `game:resign` / `game:offerDraw` / `game:requestTakeback` | 대국 조작 |
| C→S | `chat:send` (`scope: 'all' \| 'team'`) | 전체/팀 채팅 |
| S→C | `lobby:update` / `inbox:update` / `game:state` / `game:over` / `chat:all` / `chat:team` | 상태 브로드캐스트 |

`chessEngine.js`는 서버·클라이언트 양쪽에서 동일하게 로드되므로, 클라이언트는 이동
가능 칸 미리보기(하이라이트)를 서버 왕복 없이 즉시 계산합니다. 실제 이동의
합법성 최종 판정은 항상 서버(`server.js` → `Engine.makeMove`)가 수행합니다.
